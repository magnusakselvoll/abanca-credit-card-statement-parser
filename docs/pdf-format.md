# Abanca Credit Card PDF Format

Abanca credit card statements are multi-page PDFs generated by OpenText Exstream.

## Page structure

### Page 1 — Summary

Contains account metadata and financial summary for the period:

| Field | Example | Notes |
|---|---|---|
| Statement number | `0000000 000` | Internal reference |
| Card type | `VISA CLASICA` | |
| Sheet number | `1` | |
| FECHA COBRO | `31-03-2026` | Date the bank charges the balance |
| PERÍODO DE LIQUIDACIÓN | `20-02-2026 A 19-03-2026` | Billing period start and end |
| CUENTA ASOCIADA | `IBAN ES00 0000 0000 0000 0000 0000` | Associated bank account |
| N° TARJETA | `99999-0001` | Masked card number |
| Financial totals | Various | Not parsed; used only as year anchor |

### Pages 2+ — Transactions

Each transaction page has a table with columns:

| Column | Format | Example |
|---|---|---|
| FECHA | `dd-mm-yy` | `18-02-26` |
| TARJ. | 2-digit code | `00` |
| CONCEPTO | Free text | `APPLE.COM/BILL ITUNES.COM` |
| MOVIMIENTOS | `amount D/H` | `9,99 D` |
| COMISIONES | Usually empty | |

**D** = Debe (debit / charge). **H** = Haber (credit / refund or payment).

The last row of the transaction table is:

```
TOTAL OPERACIONES TARJETA  ****  ****  8001   1.088,15
```

This total equals: Σ(D amounts) − Σ(H amounts excluding AMORTIZACION DEUDA).

## Special rows

### AMORTIZACION DEUDA

The first row of the transaction table is always the previous month's payment, recorded as an `H` (credit) transaction:

```
28-02-26  00  AMORTIZACION DEUDA  135,94 H
```

This row is included in the output CSV as a positive `Importe` (the parser marks it with `IsAmortizacionDeuda = true` for verification purposes only).

## Amount format

Amounts use Spanish locale notation:
- Thousands separator: `.` (period)
- Decimal separator: `,` (comma)
- Always 2 decimal places

Examples: `9,99` · `135,94` · `1.088,15`

## Date format

- Page 1 header dates: `dd-MM-yyyy` (4-digit year, e.g. `31-03-2026`)
- Transaction row dates: `dd-MM-yy` (2-digit year, e.g. `18-02-26`)

The parser uses the first 4-digit-year date found in the PDF as a century anchor to expand 2-digit years. This correctly handles statements that span a December → January year boundary.

## Transaction row regex

```
^\s*(\d{2}-\d{2}-\d{2})\s+(\d{2})\s+(.+?)\s+([\d\.]+,\d{2})\s+([DH])\s*$
```

Groups: date, card code (discarded), description, amount, sign.
